每个文件单独开关

重要的导图打开自动保存，临时草稿保持原样。新文件默认关闭；在同一磁盘内改名或移动后，设置依然保留。

  • 开关就在标题栏旁

    悬浮在 XMind 窗口顶部，一眼看到当前文件是否在自动保存；全屏或演说时自动隐藏。

  • 安静地待在后台

    macOS 上只在菜单栏，Windows 上在任务栏通知区域；登录后自动启动，不想要时随时关掉。

  • 不联网，不碰你的文件

    不读取导图内容，按键只记录时刻、不记录内容，只向 XMind 发送 ⌘S。

安装

一分钟，装好就能用。

装好后安静地待在后台：macOS 上在菜单栏，Windows 上在任务栏通知区域。

  1. 1

    拖入“应用程序”

    打开下载好的 DMG，把 XMindAutoSave.app 拖进 Applications。

  2. 2

    首次右键打开

    在“应用程序”中按住 Control 点按 App，选择“打开”，再确认一次“打开”。

  3. 3

    允许辅助功能

    按提示前往“系统设置 → 隐私与安全性 → 辅助功能”，允许 XMindAutoSave。

  4. 4

    点亮开关

    回到 XMind 打开文档，点亮标题栏旁的“自动保存”，这个文件就交给它了。

为什么第一次需要右键打开？

当前版本还没有 Apple 开发者证书，因此无法进行苹果公证。安装包使用 macOS 临时签名并公开全部源码，但 Gatekeeper 仍会在第一次打开时请你手动确认。之后就和普通 App 一样。

  1. 1

    运行安装程序

    双击下载好的 XMindAutoSave-Setup，它会装到当前用户目录，不需要管理员权限。

  2. 2

    首次允许运行

    如果看到“Windows 已保护你的电脑”，点“更多信息”，再点“仍要运行”。

  3. 3

    在通知区域找到它

    它会出现在任务栏右下角（可能收在 ^ 里），并随 Windows 登录自动启动。

  4. 4

    点亮开关

    回到 XMind 打开文档，点亮标题栏旁的“自动保存”，这个文件就交给它了。

为什么会出现“Windows 已保护你的电脑”？

当前版本还没有代码签名证书，SmartScreen 会对新下载的程序提示一次。源码全部公开，程序不联网，也不需要管理员权限。之后就和普通程序一样。Windows 版目前是测试版，遇到问题欢迎反馈。

常见问题

还有疑问？

找不到答案，可以直接在 GitHub Issues 里提问。

它会读取或上传我的导图内容吗？

不会。程序完全不联网，也不读取导图内容。它只读取 XMind 当前窗口的辅助功能信息（例如文件路径和“已编辑”状态），并且只向 XMind 发送保存快捷键（macOS 上是 ⌘S，Windows 上是 Ctrl+S）。键盘监听只用来判断“你是否还在输入”，不会记录按下了哪些键。

为什么需要“辅助功能”权限？

macOS 规定，读取其它 App 的窗口信息、以及向其它 App 发送快捷键，都需要“辅助功能”授权。没有这项权限，它就无法知道 XMind 当前打开的是哪个文件，也无法帮你按下 ⌘S。Windows 版不需要额外授权。

支持哪些 XMind 版本？

macOS 版在 XMind 26.02 上验证，中文和英文界面都可以识别（“已编辑 / Edited”）。Windows 版是测试版，每次更新都会在 GitHub 上自动安装最新版 XMind 做端到端测试。两者都依赖 XMind 的辅助功能界面结构，如果 XMind 以后大幅改版，可能需要同步适配。

设置保存在哪里？怎么卸载？

每个文件的开关记录在 ~/Library/Application Support/XMindAutoSave/preferences.json。卸载时，先在菜单栏取消“登录时自动启动”，退出程序，再删除 /Applications/XMindAutoSave.app；如需清除开关记录，一并删除上面的文件夹即可。

Windows 上，开关记录在 %APPDATA%\XMindAutoSave\preferences.json。卸载时打开“设置 → 应用 → 已安装的应用”，找到“XMind 自动保存”卸载即可，过程中可以选择是否一并删除开关记录。

Windows 版和 macOS 版有什么不同？

Windows 不允许向后台窗口发送快捷键，所以只在 XMind 位于前台时保存；编辑后不到 1.2 秒就切到别的程序时，会在回到 XMind 后补存。使用中文输入法时，拼音还没上屏不会触发保存，以免打断输入。遇到识别不到文件等问题，可以点通知区域图标里的“生成诊断报告”，附在 GitHub Issue 里。
